Guia para crear un nuevo modulo en el framework Selenium Cucumber

Esta guia explica el flujo basico para crear un modulo nuevo dentro del framework: primero se crea el archivo .feature, luego la Page, y despues los Steps. La idea es separar claramente que se prueba, como se conecta con Java, y como Selenium ejecuta la accion real.

Regla principal: el Selenium va en la clase Page. Los Steps solo conectan frases de Cucumber con metodos Java.

1. Estructura general

Para un modulo nuevo se crean tres piezas principales:

Pieza Ruta Responsabilidad
Feature src/test/java/auto/framework/selenium/cucumber/features/Regression/MiModulo Describe el escenario en lenguaje Gherkin.
Page src/test/java/auto/framework/selenium/pages/baxter_page/MiModuloPage.java Contiene localizadores y acciones Selenium.
Steps src/test/java/auto/framework/selenium/cucumber/steps/MiModuloSteps.java Conecta frases del feature con metodos de la Page.

El flujo queda asi:

Feature -> Steps -> Page -> Selenium/WebDriver

2. Crear la carpeta del modulo

Si el modulo se llama Search, la carpeta se crea dentro de Regression: 

src/test/java/auto/framework/selenium/cucumber/features/Regression/Search

Si el modulo se llama Medication, seria: 

src/test/java/auto/framework/selenium/cucumber/features/Regression/Medication

La carpeta sirve para agrupar los escenarios del modulo y mantener el proyecto ordenado.

3. Crear el Feature

Ejemplo basado en el modulo Search:

Archivo:

src/test/java/auto/framework/selenium/cucumber/features/Regression/Search/ViewSearch.feature
@Environment_dev @versia_renal @3.2 @Search @regression
Feature: Search - View search results

  Background:
    Given I open the Baxter website
    And   I try to login with "login_baxter" credentials
    And   I login successful

  Scenario: View search results
    When  I click search icon

Explicacion linea por linea

Linea Para que sirve
@Environment_dev @versia_renal @3.2 @Search @regression Son tags. Permiten ejecutar grupos de pruebas por ambiente, version, modulo o tipo de prueba.
Feature: Search - View search results Nombre funcional de la caracteristica que se esta probando.
Background: Pasos comunes que se ejecutan antes de cada escenario del archivo.
Given I open the Baxter website Abre la aplicacion. Este step ya existe en el framework.
And I try to login with "login_baxter" credentials Hace login usando credenciales definidas en la configuracion.
And I login successful Valida que el login fue correcto.
Scenario: View search results Define el caso de prueba concreto.
When I click search icon Accion del escenario. Esta frase debe existir en una clase Steps con @When.

4. Crear la Page

La Page es donde vive Selenium. Aqui se definen los elementos de pantalla y los metodos que hacen click, escriben, esperan, validan o navegan.

Archivo:

src/test/java/auto/framework/selenium/pages/baxter_page/SearchPage.java
package auto.framework.selenium.pages.baxter_page;

import auto.framework.selenium.annotations.LazyComponent;
import auto.framework.selenium.pages.BasePage;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.FindBy;
import org.openqa.selenium.support.How;
import org.openqa.selenium.support.ui.ExpectedConditions;

@LazyComponent
public class SearchPage extends BasePage<SearchPage> {

    @FindBy(how = How.XPATH, using = "//*[contains(@class,'fa-search') or contains(@class,'glyphicon-search') or contains(@class,'k-i-search')]/ancestor::*[self::button or self::a or self::li or self::span][1]")
    private WebElement btnSearchIcon;

    @Override
    public boolean isAt() {
        return wait.until((d) -> btnSearchIcon.isDisplayed());
    }

    public void clickSearchIcon() throws InterruptedException {
        wait.until(ExpectedConditions.elementToBeClickable(btnSearchIcon));
        click(btnSearchIcon);
        pause(500);
    }
}

Explicacion de la Page

Linea Explicacion
package auto.framework.selenium.pages.baxter_page; Indica que esta clase pertenece al paquete de Pages de la aplicacion Baxter.
import auto.framework.selenium.annotations.LazyComponent; Importa la anotacion propia del framework para registrar esta Page en Spring.
import auto.framework.selenium.pages.BasePage; Permite heredar metodos comunes como click, pause y el objeto wait.
import org.openqa.selenium.WebElement; Representa un elemento HTML de la pagina.
import org.openqa.selenium.support.FindBy; Permite declarar elementos con anotaciones en lugar de buscarlos manualmente.
import org.openqa.selenium.support.How; Permite indicar el tipo de localizador: XPATH, ID, CSS, NAME, etc.
import org.openqa.selenium.support.ui.ExpectedConditions; Permite usar condiciones de espera, por ejemplo esperar que un boton sea clicable.
@LazyComponent Le dice a Spring que esta clase puede ser creada e inyectada cuando se necesite.
public class SearchPage extends BasePage<SearchPage> Declara la clase Page y hereda de BasePage para reutilizar acciones comunes.
@FindBy(...) Define como Selenium encuentra el elemento en la pantalla.
private WebElement btnSearchIcon; Guarda la referencia al boton/icono de busqueda.
@Override public boolean isAt() Metodo para validar si la Page esta en la pantalla esperada.
wait.until(...) Espera explicita. Evita fallos por intentar usar un elemento antes de que cargue.
click(btnSearchIcon); Usa el metodo comun de BasePage para hacer click.
pause(500); Pausa corta despues de la accion. En general es mejor usar esperas explicitas cuando sea posible.

5. Crear los Steps

Los Steps conectan el texto del feature con Java. No deben contener Selenium directo.

Archivo:

src/test/java/auto/framework/selenium/cucumber/steps/SearchSteps.java
package auto.framework.selenium.cucumber.steps;

import auto.framework.selenium.annotations.LazyAutowired;
import auto.framework.selenium.pages.baxter_page.SearchPage;
import io.cucumber.java.en.When;

public class SearchSteps {

    @LazyAutowired
    private SearchPage searchPage;

    @When("I click search icon")
    public void iClickSearchIcon() throws InterruptedException {
        searchPage.clickSearchIcon();
    }
}

Explicacion de los Steps

Linea Explicacion
package auto.framework.selenium.cucumber.steps; Indica que esta clase pertenece al paquete de Steps de Cucumber.
import auto.framework.selenium.annotations.LazyAutowired; Permite inyectar la Page usando Spring de forma lazy.
import auto.framework.selenium.pages.baxter_page.SearchPage; Importa la Page que contiene la accion Selenium.
import io.cucumber.java.en.When; Permite usar la anotacion @When para conectar con Gherkin.
public class SearchSteps Clase que agrupa los pasos del modulo Search.
@LazyAutowired private SearchPage searchPage; Spring crea e inyecta la Page. Asi no se usa new SearchPage().
@When("I click search icon") Debe coincidir exactamente con la frase del feature: When I click search icon.
searchPage.clickSearchIcon(); Llama al metodo de la Page. Aqui no se escribe Selenium directamente.

6. Que es @LazyComponent

@LazyComponent es una anotacion creada en el framework para combinar varias anotaciones de Spring: 

@Lazy
@Component
@Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)
public @interface LazyComponent {
}
Anotacion Significado
@Component Spring puede detectar y crear esta clase automaticamente.
@Lazy La clase no se crea hasta que realmente se necesita.
@Scope(PROTOTYPE) Spring crea una instancia nueva cuando se solicita. Es util para Pages en pruebas.

7. Que es @LazyAutowired

@LazyAutowired tambien es una anotacion propia del framework. Combina @Autowired y @Lazy. 

@Lazy
@Autowired
public @interface LazyAutowired {
}

Se usa en los Steps para pedirle a Spring una Page: 

@LazyAutowired
private SearchPage searchPage;

Gracias a esto no se crean objetos manualmente. Spring administra las dependencias.

8. Plantilla general para un modulo nuevo

Feature

@Environment_dev @versia_renal @3.2 @MiModulo @regression
Feature: MiModulo - View screen

  Background:
    Given I open the Baxter website
    And   I try to login with "login_baxter" credentials
    And   I login successful

  Scenario: Open MiModulo
    When I click MiModulo option

Page

package auto.framework.selenium.pages.baxter_page;

import auto.framework.selenium.annotations.LazyComponent;
import auto.framework.selenium.pages.BasePage;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.support.FindBy;
import org.openqa.selenium.support.How;
import org.openqa.selenium.support.ui.ExpectedConditions;

@LazyComponent
public class MiModuloPage extends BasePage<MiModuloPage> {

    @FindBy(how = How.XPATH, using = "TU_XPATH_AQUI")
    private WebElement btnMiModulo;

    @Override
    public boolean isAt() {
        return wait.until((d) -> btnMiModulo.isDisplayed());
    }

    public void clickMiModuloOption() throws InterruptedException {
        wait.until(ExpectedConditions.elementToBeClickable(btnMiModulo));
        click(btnMiModulo);
    }
}

Steps

package auto.framework.selenium.cucumber.steps;

import auto.framework.selenium.annotations.LazyAutowired;
import auto.framework.selenium.pages.baxter_page.MiModuloPage;
import io.cucumber.java.en.When;

public class MiModuloSteps {

    @LazyAutowired
    private MiModuloPage miModuloPage;

    @When("I click MiModulo option")
    public void iClickMiModuloOption() throws InterruptedException {
        miModuloPage.clickMiModuloOption();
    }
}

9. Checklist antes de compilar

  • La frase del feature debe coincidir exactamente con la anotacion del Step.
  • La Page debe tener @LazyComponent.
  • El Step debe inyectar la Page con @LazyAutowired.
  • El Step no debe tener Selenium directo.
  • El nombre de la clase Page y el import del Step deben coincidir.
  • El XPath o localizador debe apuntar a un elemento real.
  • Antes de subir cambios, ejecutar .\mvnw.cmd clean test-compile o mvn clean test-compile.
Error comun: si Maven dice cannot find symbol, normalmente significa que el Step esta importando una Page que no existe, o que el nombre de la clase no coincide con el nombre del archivo.

10. Orden recomendado de trabajo

  1. Crear carpeta del modulo dentro de features/Regression.
  2. Crear el archivo .feature con tags, background y escenario.
  3. Crear la clase Page con localizadores y metodos Selenium.
  4. Crear la clase Steps conectando frases del feature con la Page.
  5. Compilar con Maven.
  6. Ejecutar el escenario por tag.
  7. Hacer commit cuando el feature funcione.
